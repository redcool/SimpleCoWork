## 1. 范围与约束说明

### 1.1 事实依据 (Facts)
*   **输入文件集**: 本规格基于以下 v_2 需求文件生成：
    *   `requirements.en.md` / `requirements.zh.md`: 定义核心游戏循环与胜利条件。
    *   `feature-list.en.md` / `feature-list.zh.md`: 列出功能模块优先级。
    *   `asset-spec.en.md` / `asset-spec.zh.md`: 定义资源尺寸、格式与加载策略。
    *   `acceptance.en.md` / `acceptance.zh.md`: 提供验收测试用例。
    *   `layer-manifest.json`: 定义当前工程层级依赖。
*   **引擎假设**: 基于 `layer-manifest.json` 中常见的 3D 架构标记，假设目标引擎为 Unity 3D 或 Unreal Engine 5（需工程侧确认，下文以 Unity URP 为例进行量化，若为 UE 需对应调整单位）。
*   **性能基线**: 假设目标平台为 PC (Windows 10+) 及主流移动设备（中端配置）。

### 1.2 假设 (Assumptions)
*   **帧率目标**: 锁定 60 FPS 作为基准目标。
*   **玩家规模**: 单局最大敌人数量为 500（需根据 Brotato 原版数据修正，此处为假设值，需策划确认）。
*   **资源上限**: 单个场景最大绘制调用 (Draw Call) 不超过 100。

## 2. 核心功能量化指标

### 2.1 游戏循环逻辑
**来源**: `requirements.zh.md` - 核心玩法章节

| 指标项 | 量化规格 | 验收标准 (Acceptance Criteria) | 备注/假设 |
| :--- | :--- | :--- | :--- |
| **回合持续时间** | 每回合固定 60 秒 | 计时器误差 < ±100ms；回合结束瞬间所有输入锁定 < 50ms | 需高精度计时器 |
| **冷却时间 (CD)** | 技能 CD 范围: 1s - 30s | CD 倒计时 UI 更新频率 ≥ 10Hz；点击无效状态时反馈延迟 < 100ms | 假设技能系统独立于攻击节奏 |
| **资源生成速率** | 每回合结束时生成金币 | 生成数量 = 基础值 × (1 + 玩家等级 × 0.1)；生成动画播放时间 < 2s | 需定义基础金币值 |
| **商店刷新机制** | 每回合商店物品独立随机 | 刷新耗时 < 50ms；物品权重分布符合 `feature-list` 定义 | 假设使用确定性种子随机 |

### 2.2 战斗系统
**来源**: `feature-list.zh.md` - 战斗模块

| 指标项 | 量化规格 | 验收标准 | 备注/假设 |
| :--- | :--- | :--- | :--- |
| **攻击帧判定** | 攻击有效窗口 (Hitbox Active) 持续 0.2s | Hitbox 激活与关闭状态切换无残影；碰撞检测帧间隔 ≤ 1/60s | 假设基于物理引擎碰撞 |
| **伤害计算精度** | 最终伤害 = Base × (1 - EnemyResist) | 伤害数值显示与实际扣血一致，误差 < 1%；浮点运算使用 float32 | 需定义抗伤公式 |
| **敌人 AI 反应** | 敌人受击后停止当前动作 < 0.1s | 受击反馈特效同步率 100%；无动作打断冲突 | 假设使用状态机控制 |
| **最大同屏敌人** | 500 个 | 在中端 GPU (GTX 1650 / M1) 下，500 敌人时 FPS ≥ 45 | **关键性能指标** |

### 2.3 资源加载与管理
**来源**: `asset-spec.zh.md`

| 指标项 | 量化规格 | 验收标准 | 备注/假设 |
| :--- | :--- | :--- | :--- |
| **模型面数限制** | 主角模型 ≤ 5,000 Triangles; 敌人模型 ≤ 2,000 Triangles | 所有 LOD0 模型符合上限；超出部分需提交美术优化报告 | 假设 LOD 级别为 0-3 |
| **贴图分辨率** | 主角 2048x2048; 敌人 512x512; UI 1024x1024 | 贴图尺寸符合规格；内存占用 < 100MB (所有角色加载后) | 使用 ASTC/BC7 压缩 |
| **预加载策略** | 游戏加载至主菜单 < 5s | 首包大小 ≤ 500MB；加载进度条平滑更新 (无卡顿帧) | 假设使用 AssetBundle 或 Addressables |
| **对象池复用** | 弹道、敌人尸体 100% 复用 | 运行时 GC Alloc (C#) 峰值 < 5MB/round；无 `new` 分配在热路径 | **硬性性能指标** |

## 3. 性能预算 (Performance Budget)

> 以下指标为**假设值**，需工程团队在 v_2 开发中期通过 Profiler 验证并动态调整。

### 3.1 CPU 侧
*   **主线程更新耗时**: < 8ms (60FPS)
*   **物理模拟耗时**: < 5ms
*   **AI 寻路耗时**: 单敌人 < 0.5ms; 批量寻路每帧预算 < 10ms
*   **C# GC 分配**: 稳态下 < 1MB/s

### 3.2 GPU 侧
*   **Draw Calls**: 主战斗场景 < 100
*   **顶点处理**: 总面数 < 500,000 Tris (所有可见模型)
*   **Shader 复杂度**: 禁止在移动端使用 PBR 高光计算；使用 URP Lit 简版或 Unlit

### 3.3 内存侧
*   **总内存占用**: < 2GB (PC), < 512MB (Mobile High)
*   **纹理内存**: < 500MB
*   **模型内存**: < 200MB

## 4. 验收证据与测试策略 (Acceptance & Evidence)

### 4.1 自动化测试覆盖
*   **单元测试**: 伤害公式、冷却计算、随机种子验证。覆盖率要求 ≥ 80%。
*   **集成测试**: 加载完整回合（从开始到结束）无崩溃；商店刷新 100 次无内存泄漏。
*   **压力测试**: 生成 500 敌人持续运行 30 分钟，监控 FPS 曲线与内存增长。
    *   *证据*: 导出 Profiler 报告 + 内存快照对比。

### 4.2 手动验收清单 (基于 `acceptance.zh.md`)
| 测试用例 ID | 描述 | 通过标准 | 证据要求 |
| :--- | :--- | :--- | :--- |
| AC-001 | 玩家死亡流程 | 死亡后 1.5s 内弹出结算界面；无卡顿 | 视频录屏 + 帧率数据 |
| AC-002 | 技能叠加 | 两个同类技能同时释放，特效不重叠消失 | 视频录屏 |
| AC-003 | 商店购买 | 点击购买，金币扣除与物品入包同步 < 100ms | 日志记录时间戳 |
| AC-004 | 断点续玩 | 中途退出后重进，回合状态、金币、角色等级一致 | 数据库快照对比 |

### 4.3 性能验收门槛
*   **FPS 地板**: 最低帧率不低于 45 FPS（PC 中端配置）。
*   **加载时间**: 冷启动至可交互状态 < 8s。
*   **崩溃率**: 内测期间 crash-free < 99.5%。

## 5. 风险与未决项 (Risks & Open Questions)

| 风险项 | 类型 | 影响 | 缓解措施 |
| :--- | :--- | :--- | :--- |
| 500 敌人 AI 性能瓶颈 | 技术假设 | 高 | 预研行为树 vs 状态机性能；引入 GPU 剔除；LOD 距离优化 |
| 移动端贴图内存超限 | 资源约束 | 中 | 降低移动端纹理尺寸至 1024x1024；启用 ASTC 压缩 |
| 物理引擎碰撞抖动 | 事实/假设 | 中 | 使用固定时间步长物理模拟；禁用动态物体互撞 |
| 随机种子确定性 | 逻辑 | 低 | 使用 Mersenne Twister；保存种子至存档 |

## 6. 工程实施要求 (Engineering Handoff)

1.  **代码规范**:
    *   热路径（Update, FixedUpdate）禁止分配内存。
    *   所有配置数据（技能、敌人属性）必须从 JSON/ScriptableObject 加载，硬编码禁止。
2.  **资源管线**:
    *   所有模型需在 Blender/DCC 中归一化：尺寸 1.8m (角色), Y 轴向上。
    *   贴图命名规范：`[Type]_[Name]_[Resolution]` (e.g., `T_P_Brotato_2048`).
3.  **版本控制**:
    *   本规格文件 (`quantified-spec.md`) 纳入 Git 管理。
    *   任何指标变更需提交 PR，并由策划组组长审批。
