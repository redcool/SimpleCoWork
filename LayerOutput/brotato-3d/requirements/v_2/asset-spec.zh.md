# 资产规格文档 (asset-spec.md)

## 1. 文档概述与需求分解

### 1.1 原始输入
*   **输入类型**：Idea (创意概念)
*   **核心概念**：做一个3D版本的《土豆兄弟》(Brotato)。
*   **原始描述**："做一个3d的土豆兄弟"

### 1.2 事实 (Facts) 与假设 (Assumptions) 区分

为了确保开发资源的有效分配，必须明确当前阶段的认知边界：

| 类别 | 内容描述 | 状态 | 影响范围 |
| :--- | :--- | :--- | :--- |
| **事实 (Fact)** | 原型参考为《Brotato》 (Brotato)。 | 已确认 | 核心玩法逻辑、数值平衡参考基准 |
| **事实 (Fact)** | 视角与维度变更为 3D。 | 已确认 | 渲染管线、碰撞检测、摄像机系统、UI适配 |
| **假设 (Assumption)** | 美术风格：低多边形 (Low-Poly) 或 卡通风格。 | **待确认** | 直接影响模型面数、材质复杂度、贴图规格 |
| **假设 (Assumption)** | 目标平台：PC 优先，兼顾移动端？ | **待确认** | 决定性能预算 (Draw Call, 阴影质量, 粒子数量) |
| **假设 (Assumption)** | 角色形象：仍为"土豆"形态，还是抽象几何体？ | **待确认** | 决定角色建模规范与动画绑定 |
| **假设 (Assumption)** | 武器交互：3D环境下武器如何挂载与显示？ | **待确认** | 影响武器资产规格与骨骼绑定方案 |

> **策划组决策建议**：在制作正式高精度资产前，优先验证 **Assumption 1 (美术风格)** 和 **Assumption 4 (武器交互)**。建议首版资产采用 Placeholder (占位符) 或低模原型，避免过早投入高成本美术资源。

### 1.3 核心玩法映射至 3D 的资产需求变化

相比 2D 的 Brotato，3D 化主要带来以下资产维度的变化：

1.  **角色 (Protagonist)**：从 2D 精灵图序列 -> 3D 模型 (Mesh) + 骨骼 (Rig) + 材质 (Material)。需要定义面数上限、贴图尺寸。
2.  **敌人 (Enemies)**：从 2D 单元 -> 3D 模型。需要定义视口距离剔除策略 (LOD)。
3.  **地图 (Arena)**：从 2D 网格/Tile -> 3D 场景 (Level Geometry)。需要定义地形、掩体、装饰物的模块化资产规范。
4.  **特效 (VFX)**：从 2D 序列帧 -> 3D 粒子系统 + 网格模型特效。
5.  **UI/HUD**：从 2D UI -> 3D 空间中的 UI 锚点 + 屏幕空间 UI 混合。

## 2. 详细资产规格 (Detailed Asset Specs)

以下规格基于 **中等性能预算** 假设（目标：PC 中端显卡 1080p 60FPS，移动端高配 30-60FPS）。

### 2.1 角色资产 (Protagonist)

| 属性 | 规格要求 | 验收标准 / 证据 (Acceptance Criteria / Evidence) |
| :--- | :--- | :--- |
| **模型** | 非人形角色 (土豆形态)，面数 ≤ 5,000 tris。顶点数 ≤ 3,000。 | 在引擎中加载后，显示网格统计信息。无拓扑错误。 |
| **贴图** | 1 张漫反射 (Albedo/Diffuse) 1024x1024。1 张法线 (Normal) 1024x1024 (可选，取决于风格)。 | 贴图无拉伸，UV 布局无重叠。材质在标准光照下显示正确。 |
| **材质** | PBR 或半 PBR (仅 Diffuse+Normal)。无透明通道 (避免排序问题)，除非特效需要。 | 渲染队列正常，无 Z-fighting。移动时材质无闪烁。 |
| **动画** | 基础动作：Idle, Run, Attack (若需), Hit。 | 动画播放流畅，无滑脚 (Foot Sliding)。在 3D 空间中运动轨迹正确。 |
| **骨骼** | 若为动态土豆，需简单骨骼 (根骨 + 身体 + 可能的手臂)。若为刚体，则无需骨骼。 | 权重归一化 (Weight Normalization) 检查通过，变形无破碎。 |

### 2.2 敌人资产 (Enemies)

由于 Brotato 包含大量不同敌人，建议采用 **模块化敌人系统**。

| 属性 | 规格要求 | 验收标准 / 证据 |
| :--- | :--- | :--- |
| **基础敌人模型** | 面数 ≤ 2,000 tris / 个体。 | 单个敌人资产大小 < 500KB (含贴图)。 |
| **群体渲染** | 支持 GPU Instancing (实例化渲染)。 | 在场景中生成 100 个同类敌人时，Draw Call 数量保持为 1 或接近 1。 |
| **LOD (视距细节)** | LOD0 (近距离): 全模。<br>LOD1 (中距离): 面数减少 50%。<br>LOD2 (远距离): 替换为 Billboarding 或 低模。 | 切换 LOD 时视觉跳跃不明显。性能测试中，远处敌人不增加 CPU 负担。 |
| **动画** | 每类敌人需独立 Idle/Movement 动画。 | 动画与移动速度同步，无穿模。 |

### 2.3 地图与环境资产 (Arena & Environment)

Brotato 的地图是固定的竞技场，3D 化后需定义场景结构。

| 属性 | 规格要求 | 验收标准 / 证据 |
| :--- | :--- | :--- |
| **地形网格** | 单一网格 (Single Mesh) 或 模块化拼接。面数 ≤ 10,000 tris。 | 地形碰撞体 (Collider) 与可视网格精确匹配。 |
| **掩体/障碍** | 模块化方块/圆柱等。面数 ≤ 500 tris / 模块。 | 掩体可被破坏 (若有此机制) 时，碎片资产预制体已准备。 |
| **装饰物** | 静态道具 (路灯、箱子等)。面数 ≤ 1,000 tris。 | 支持静态批处理 (Static Batching) 或 GPU 实例化。 |
| **光照** | 预烘焙光照贴图 (Baked Lightmaps) 或 实时全局光照 (取决于平台)。 | 阴影投射正确。无光照泄漏 (Light Leaking)。 |

### 2.4 武器与投射物资产 (Weapons & Projectiles)

3D 化的关键难点：武器在角色身上的挂载方式。

| 属性 | 规格要求 | 验收标准 / 证据 |
| :--- | :--- | :--- |
| **武器挂载** | 每个武器预制体需定义 `Socket` (插槽) 位置或 相对偏移。 | 装备不同武器时，模型正确贴合角色，无穿插。 |
| **投射物 (Bullet)** | 面数 ≤ 100 tris。支持拉伸变形 (Stretching) 模拟速度感。 | 高速运动时，投射物不穿模 (Raycast 检测或 Sweep 检测)。 |
| **特效 (VFX)** | 粒子发射器 + 网格特效。总粒子数上限：单屏 500 个。 | 在满屏投射物时，帧率下降 < 10%。 |

### 2.5 UI 与 HUD 资产

| 属性 | 规格要求 | 验收标准 / 证据 |
| :--- | :--- | :--- |
| **主菜单/商店** | 2D UI，但需适配 3D 摄像机视角变化。 | 当玩家旋转视角时，UI 不旋转，始终面向屏幕。 |
| **物品图标** | 3D 模型渲染的 2D 图标 (Icon)。尺寸 128x128 或 256x256。 | 图标清晰可辨，无背景干扰。 |
| **血条/冷却** | 屏幕空间 UI。 | 数值变化时，UI 有明确的视觉反馈 (颜色变化、跳动)。 |

## 3. 技术约束与性能预算

### 3.1 性能目标

*   **目标帧率**：60 FPS (稳定)。
*   **最大同屏实体数**：500+ (包含敌人、投射物、粒子)。
*   **Draw Call 限制**：< 200 (PC), < 100 (Mobile)。
*   **内存占用**：< 500 MB (PC), < 200 MB (Mobile)。

### 3.2 资源格式规范

*   **模型格式**：FBX (含动画) 或 GLTF (轻量化)。
*   **贴图格式**：PNG (开发阶段) / Texture Compressed (发布阶段，ASTC 或 BC7/DXBC)。
*   **命名规范**：
    *   模型：`Mesh_[Category]_[Name]_v[Version]` (例: `Mesh_Enemy_Goblin_v01.fbx`)
    *   材质：`Mat_[Category]_[Name]_v[Version]`
    *   贴图：`Tex_[Category]_[Name]_v[Version].[Albedo/Normal/etc]`

## 4. 交付物清单 (Delivery Checklist)

在资产制作阶段结束前，需交付以下文件至版本控制系统 (SVN/Git LFS)：

1.  [ ] 主角基础模型 (Mesh) + 材质 + 动画 (Idle/Run)。
2.  [ ] 5 种基础敌人模型 (Mesh) + 材质 + 基础动画。
3.  [ ] 1 个标准竞技场场景 (Terrain + Obstacles + Lighting)。
4.  [ ] 3 种基础武器模型 (Gun/Sword/Blade) + 投射物模型。
5.  [ ] UI 图标集 (Shop Items, Stats, Menu)。
6.  [ ] VFX 包：击中特效、爆炸特效、死亡粒子。

## 5. 风险与缓解措施

| 风险项 | 概率 | 影响 | 缓解措施 |
| :--- | :--- | :--- | :--- |
| **3D 视角导致玩法可见性下降** | 高 | 高 | 1. 设计高对比度角色/敌人模型。<br>2. 增加轮廓线 (Rim Light) 材质。<br>3. 摄像机高度适中，避免俯视角度过大遮挡信息。 |
| **移动端性能不足** | 中 | 中 | 1. 默认关闭阴影和后期处理。<br>2. 降低纹理分辨率。<br>3. 使用 LOD 系统。 |
| **武器在 3D 空间中遮挡视线** | 中 | 中 | 1. 武器模型半透明化处理。<br>2. 第一人称/第三人称视角可选。<br>3. 武器 UI 化 (显示在屏幕边缘而非模型上)。 |

## 6. 下一步行动 (Next Steps)

1.  **确认美术风格**：向美术组下发 Mood Board (风格参考图)，明确是 Low-Poly、Stylized 还是 Realistic。
2.  **制作 Blockout (粗模)**：使用灰模 (Grey Box) 搭建基础场景和角色，验证 3D 玩法手感。
3.  **数值与资产联动测试**：将 3D 模型导入引擎，测试碰撞体大小与游戏数值（如射速、移动速度）是否匹配。

> **备注**：本文档仅为资产规格说明，不包含代码实现细节。所有"假设"项需在概念评审会后更新为"事实"，并重新修订规格。
